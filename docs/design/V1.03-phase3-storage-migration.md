# V1.03 阶段三：移除「所有文件访问」影响分析

目标：新安装不再申请 `MANAGE_EXTERNAL_STORAGE`，改用媒体库（MediaStore）+ 用户选择文件夹（SAF）。
本文件先说明现状、迁移方式与**系统限制带来的功能影响**，确认后再改代码。

## 1. 现状：哪些地方依赖「所有文件访问」

| 功能 | 当前位置 | 依赖方式 |
| --- | --- | --- |
| 音频扫描 | `DeviceAudioLibrary.scan` | 读 `MediaStore.Audio.Media.DATA` 取真实路径，再用 `File.listFiles()` 找同目录外挂歌词 |
| 外挂歌词读取 | `DeviceAudioLibrary.findSubtitle` | `java.io.File` 遍历音频所在目录 |
| 外挂歌词保存/删除 | `LyricsFileStore` | `java.io.File` 在音频目录旁创建/替换/删除 `.lrc` |
| 标签编辑 | `TagEditorPage` + `DocumentOps` | 通过音频 `content://` URI 读写，但底层 `TagIO` 需要可随机读写的 `File` |
| 权限判断 | `LibraryViewModel.hasStorageAccess`、`MediaAnvilApp.requestStorageAccess` | `Environment.isExternalStorageManager()` |

`AndroidManifest.xml` 中 `MANAGE_EXTERNAL_STORAGE` 与 `requestLegacyExternalStorage="true"` 是这套实现的前提。

## 2. 迁移方式（逐项）

### 2.1 音频扫描 → MediaStore（不再需要宽存储权限）

只查 `MediaStore.Audio.Media`，用 `DISPLAY_NAME` / `RELATIVE_PATH`（API 29+）代替 `DATA`。
读取权限按版本降级：

| Android 版本 | 读取权限 |
| --- | --- |
| 13+（API 33+） | `READ_MEDIA_AUDIO` |
| 6–12（API 23–32） | `READ_EXTERNAL_STORAGE` |
| 8.0 以下 | 安装即授予 |

这是标准做法，见 [Access media files from shared storage](https://developer.android.com/training/data-storage/shared/media)。

### 2.2 标签编辑 → MediaStore 写入请求 + SAF 回退

- API 30+：`MediaStore.createWriteRequest()` 弹出系统授权框，用户同意后可写该音频的标签。见 [Scoped storage](https://source.android.com/docs/core/storage/scoped)。
- API 26–29：已有 `WRITE_EXTERNAL_STORAGE`（`maxSdkVersion=29`）即可直接写。
- **风险**：`ContentResolver.update()` 只能改 MediaStore 数据库字段，不能改写音频文件内部的 ID3/Vorbis 标签。
  当前实现是把标签**写进音频文件本身**。要在 API 30+ 保留这一点，必须让用户授予该音频所在文件夹的 SAF 权限。

### 2.3 外挂歌词读写 → 必须使用 SAF 文件夹授权

`.lrc` / `.srt` / `.vtt` 不是媒体文件，MediaStore 不索引它们，**没有任何权限能让应用在 API 30+ 直接写音频同目录下的歌词文件**。
唯一可行路径是 `ACTION_OPEN_DOCUMENT_TREE` 让用户选择音乐文件夹，再用 `DocumentFile` 在目录内创建/替换/删除歌词。

应用已有该选择器（`DeviceAudioLibrary.folderPickerIntent`）并会持久化授权，但目前仅用于限定扫描范围。

## 3. 系统限制导致的功能影响（需要你确认）

1. **外挂歌词保存需要用户先选一次文件夹。**
   未授权时，在线歌词搜索的结果将无法保存到音频旁，只能提示用户先选择音乐文件夹。
   → 这是移除宽权限的**必然代价**，无法绕过。

2. **标签编辑可能需要额外的文件夹授权。**
   若只做 MediaStore 写入，Android 可能只更新数据库而音频文件内标签不变（搜索结果中已有多起 `update()` 返回 0 行的报告）。
   为保证「标签编辑经过真机验证」这一验收项，建议同样要求文件夹授权。

3. **首启动流程改变。**
   媒体库为空时不再引导去「所有文件访问」设置页，而是请求音频读取权限；若用户拒绝，则列表为空但不崩溃。

4. **API 29 及以下的旧设备**保留 `WRITE_EXTERNAL_STORAGE` 路径，功能与现在一致。

5. **极端情况**：音频位于用户未授权的文件夹时，可正常**播放**（MediaStore 读取足够），但**不能写歌词或改标签**。

## 4. 建议的交互方案（待确认）

- 首次进入媒体页：请求音频读取权限（`READ_MEDIA_AUDIO` / `READ_EXTERNAL_STORAGE`）→ 立即可以扫描和播放。
- 首次要**保存歌词**或**编辑标签**时：提示并打开文件夹选择器，用户选择音乐文件夹后持久授权，之后不再打扰。
- 设置页保留「扫描范围 / 添加文件夹」入口，并在其中说明授权用途。

## 5. 验证计划

- 单元测试：`RELATIVE_PATH` / 目录解析、SAF 相对路径换算、权限分支判断。
- 真机（vivo V2520A，Android 16）：
  - [x] 全新安装不出现「所有文件访问」授权页
  - [x] 拒绝读取权限时不崩溃
  - [x] 授予音频权限后可扫描并播放
  - [x] 选择文件夹后歌词可保存/替换/删除
  - [x] 标签编辑写入音频文件并经 MediaStore 复核
  - [x] V1.02 覆盖升级后原分组/收藏/播放位置仍在
- CI 的模拟器任务（API 35）执行 instrumented 测试。

> 以上六项已于 2026-09-23 在真机全部完成，逐项结果与证据见
> `docs/testing/V1.03-phase3-verification.md`。
>
> 其中「选择文件夹后歌词可保存/替换/删除」在验证时暴露了一个真实缺陷：文件提供程序
> 按 MIME 类型补扩展名，把 `song.lrc` 存成了 `song.lrc.txt`，导致重新扫描找不到、
> 也删不掉。已修复并随 **1.04** 发布，详见 `docs/testing/V1.04-verification.md`。

## 6. 回退

改动集中在 `DeviceAudioLibrary`、`LyricsFileStore`、`TagEditorPage`/`DocumentOps` 与权限请求处；
`MANAGE_EXTERNAL_STORAGE` 在功能验证通过前**先保留**，验证完成后再单独提交移除，便于回退。
