# V1.03 阶段四验证记录：拆分 ViewModel 与迁移 DataStore

测试日期：2026-09-23
设备：vivo V2520A（Android 16 / API 36），debug 包 `com.imankoppai.mediaanvil.debug`
工具链：JDK 17、Android SDK 36（Build Tools 36.0.0）、Gradle 9.6.0

## 本阶段改动

### 1. 存储：SharedPreferences → Preferences DataStore

新增 `data/SettingsStore.kt`：

- 基于 `androidx.datastore:datastore-preferences:1.2.1`，文件为 `files/datastore/mediaanvil_settings.preferences_pb`。
- **读取保持同步**：首次构造时读一次快照到内存，之后读取是内存查找。调用方（`PlaybackPreferences`、播放服务的通知按钮、启动时的主题控制器）无需改成挂起函数，首次构造的一次阻塞读与原先 `getSharedPreferences()` 的首次磁盘开销相同。
- 写入立即更新快照并**异步落盘**；少数「进程可能马上消失」的调用（睡眠定时截止时间、播放位置快照、备份恢复）走同步写。
- 新增 `flush()` / `PlaybackPreferences.flushPendingWrites()`：SharedPreferences 的 `apply()` 由系统在进程退出时代为落盘，DataStore 没有这个保证，因此播放服务在 `onDestroy` 中显式等待在途写入完成。

### 2. 一次性迁移（本项目风险最高的一步）

新增 `data/SettingsMigration.kt`，迁移规划做成**纯函数**（不依赖 Android，可直接单测）。三条保命规则：

| 规则 | 作用 |
| --- | --- |
| 版本标记 `settings_store_version` 写进 DataStore 内部 | 崩溃或重复启动**都不会迁移两次** |
| DataStore 中已有的值**永远优先** | 迁移期间用户刚改的值不会被旧值回滚 |
| 旧的 `mediaanvil_playback.xml` **只读不删** | 迁移失败仍可恢复；已验证文件大小与 mtime 均未变 |

`SettingsStore.get()` 是进程级单例，**只持有 DataStore 与快照，不持有 Context**（初版曾持有 Context，被 lint 的 `StaticFieldLeak` 抓出后改为不持有，而不是加进基线掩盖）。

### 3. 补齐备份规则

原先 `allowBackup="true"` 却没有任何备份规则，云备份行为未定义。新增：

- `res/xml/backup_rules.xml`（API 30 及以下，`android:fullBackupContent`）
- `res/xml/data_extraction_rules.xml`（API 31+，`android:dataExtractionRules`，含 cloud-backup 与 device-transfer）

两者都**只排除** `file/update/`（已下载的更新包：体积大、恢复后无意义），歌单、收藏、播放位置、歌词偏移、自定义封面、隐藏歌曲全部随备份保留。

### 4. 拆分 ViewModel

原 `LibraryViewModel` 456 行、同时管理 6 类互不相关的状态，拆为 4 个：

| 类 | 职责 |
| --- | --- |
| `LibraryViewModel` | 媒体库扫描、选中项、外挂歌词、标签编辑回写 |
| `PlaylistViewModel` | 歌单、收藏、近期播放、隐藏歌曲 |
| `SettingsViewModel` | 语言/主题/快进快退/自动加载歌词/睡眠定时等设置状态 |
| `UpdateViewModel` | 检查更新、下载、校验、安装 |

顺带修掉一个隐患：原先 `Phase2PersistenceTest` 只清 SharedPreferences，而存储现在是进程级单例，会让用例之间互相污染、结果依赖执行顺序。已改为同时清 DataStore、旧文件并重置单例。

### 幂等性的真机反证（关键）

不只验证「迁移成功」，还**反向验证「不会迁移第二次」**：

1. force-stop 应用；
2. 把旧的 `mediaanvil_playback.xml` **替换为伪造内容**（`favorite_track_uris = ["BOGUS-REMIGRATED"]`、`library_sort = duration`）；
3. 重新启动应用；
4. 解析 DataStore：

| 检查 | 期望 | 实际 |
| --- | --- | --- |
| `BOGUS-REMIGRATED` 是否出现 | 否 | **否** ✅ |
| 伪造的 `library_sort=duration` 是否写入 | 否 | **否** ✅ |
| 原收藏 `1000034896` 是否保留 | 是 | **是** ✅ |
| 标记 `settings_store_version` 是否存在 | 是 | **是** ✅ |

即：**迁移确实只发生一次，之后的旧文件内容被完全忽略**。验证后已把旧文件还原为基线内容。
