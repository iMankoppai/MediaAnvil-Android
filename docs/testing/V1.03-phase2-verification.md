# V1.03 阶段二验证记录：搜索、收藏、最近播放和歌单

测试日期：2026-09-23
设备：vivo V2520A（Android 16 / API 36）
工具链：JDK 17、Android SDK 36（Build Tools 36.0.0）、Gradle 9.6.0

## 本阶段改动

### 1. 歌单顺序（原有实现的缺陷）

V1.02 的 `TrackGroup.trackUris` 是 `Set<String>`，集合不保留插入顺序，因此“歌单播放顺序”在旧实现下无法保证。
现改为 `List<String>`：

- 保存顺序即播放顺序，新增歌曲追加到末尾（`addTracksToGroup`），不覆盖已有顺序。
- 读取时去重但**不重新排序**，所以 V1.02 用户已有的分组不会被打乱。
- `LibraryQuery.resolve` 按保存顺序解析可用歌曲，音频被移动/删除的条目被跳过而不是中断播放。

### 2. 搜索

- 匹配范围从「歌名 / 歌手 / 文件名」扩展到**专辑**。
- 多关键词以空格分隔，采用 AND 语义：`稻香 DEER` 收窄结果而不是放宽。
- 大小写不敏感，命中文字在列表中加粗高亮。
- 逻辑抽到纯 Kotlin 的 `LibraryQuery`，便于单元测试。

### 3. 收藏

- 新增「收藏」标签页，心形按钮在歌曲列表、分组、专辑/艺术家列表均可用。
- 按添加顺序保存并整列播放；音频不可访问时自动跳过。
- 存储在 `favorite_track_uris`。

### 4. 最近播放

- **由播放服务写入**（`PlaybackService.recordPlayed`），因此在通知栏、桌面小部件或恢复队列触发的播放同样会被记录。
- 列表只展示当前仍可访问的本地歌曲，最新在前。
- 历史以 `uri<TAB>时间戳` 文本保存，解析失败的行被丢弃而不抛异常；上限 200 条。
- 不可访问的条目**保留在存储中**，避免存储卡临时卸载时清空用户历史。

### 5. 备份与恢复

- 备份 schema 升级到 2，新增 `favoriteTrackUris` 与 `playHistory`。
- **兼容 V1.02 的 schema 1 备份**：仍可导入。
- 缺少这两个字段的旧备份导入时，会保留现有收藏与历史，而不是清空。

## 真机验证

### 已完成

- 设备 `V2520A`（Android 16 / API 36）通过 ADB 正常连接。
- 确认设备上仍装有 V1.02 正式包（`com.imankoppai.mediaanvil`，`versionCode=3`、`versionName=1.02`），可作为第八阶段升级测试的基线。

### 未完成（阻塞原因）

本轮**无法在真机上安装新 APK**：测试时设备处于锁屏状态
（`dumpsys trust` 报告 `deviceLocked=1`、`isKeyguardShowing=true`），
vivo 系统要求解锁屏幕后才允许确认安装，ADB 返回：

```text
Failure [INSTALL_FAILED_ABORTED: User rejected permissions]
```

`adb install` 与 `adb shell pm install` 均被拒绝；本机未安装模拟器或 AVD，无法回退到模拟器。

因此以下需要在真机上手动确认的项目**尚未验证**，留待设备解锁后补做：

- [ ] 重启应用后收藏与最近播放仍在
- [ ] 移动或删除音频后不崩溃，且该歌曲从收藏/最近播放中消失
- [ ] 收藏列表与歌单的播放顺序与界面显示一致

已补充 `Phase2PersistenceTest`（androidTest）覆盖上述前两项的持久化契约：
它使用真实的设备端 `SharedPreferences`，并以新建实例模拟应用重启；
该测试会由 CI 的 `connectedDebugAndroidTest`（模拟器 API 35）执行。
